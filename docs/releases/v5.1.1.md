# cc-remote v5.1.1

## 中文

v5.1.1 修复更新失败后的诊断和重试体验。通信协议保持 **v83**，Claude Agent SDK 保持 **0.2.157**。

### 修复

- 发布文件下载、Relay 健康/版本检查及 SSH 操作会标明失败阶段，区分 DNS、TLS 握手或证书、连接超时、SSH 认证和 sudo 权限等原因，并给出检查方向。不回显凭证、原始远端输出或带签名的下载地址。
- 新版更新器使用持久启动回执和任务锁处理 Relay 更新重试。请求未送达时可以沿用原任务 ID 提交；任务已经启动但回执丢失时继续跟踪，不重复执行更新。
- Wrapper 安装失败时，明确区分预检查未修改旧服务、实际修改后回滚完成、自动回滚不完整，避免在预检查失败时误报“代码和数据已恢复”。

这些改动不会添加代理规则、选择节点或关闭 TLS 校验。网络故障仍需按提示检查本机网络、代理、证书或服务器配置。

### 升级

从 v5.1.0 升级不需要协议迁移，可在独立终端执行：

```sh
cc-remote update --check --version 5.1.1
cc-remote update --version 5.1.1
```

旧命令在切换到新版前仍使用原有更新逻辑。旧版遗留且缺少服务端启动回执的未完成记录，或回执存在但远端任务已消失的情况，仍需核查原任务日志和公网版本；不要删除记录来强行重跑。完整流程见[安装与升级](https://github.com/muggle-stack/cc-remote/blob/v5.1.1/docs/installation.md)。从 v82 或更早协议升级，仍需按部署指南协调全部设备的协议迁移。

发布包含六个 Relay/Wrapper 平台包、`install.sh` 和 `SHA256SUMS`，由 GitHub Actions 运行回归、平台导入检查并生成 attestation。没有新的 Desktop 或移动端安装包；发布本身不切换线上服务。

## English

v5.1.1 improves diagnosis and recovery when updates fail. Wire protocol remains
**v83**, and Claude Agent SDK remains **0.2.157**.

### Fixes

- Identify the failing release download, Relay health/version check or SSH
  operation. Distinguish DNS, TLS handshake/certificate, timeout, SSH
  authentication and sudo failures with actionable checks, without exposing
  credentials, raw remote output or signed download URLs.
- Use durable remote launch receipts and a per-job lock for Relay update
  retries. Requests lost before delivery can submit the original job ID;
  accepted jobs with lost acknowledgements are followed without another launch.
- Report Wrapper preflight failures with no service changes separately from
  completed or incomplete rollback. Do not claim code/data restoration when
  activation never started.

The updater does not add proxy rules, select proxy nodes or disable TLS
verification. Network problems require checking the local network, proxy,
certificates or server configuration as indicated.

### Upgrade

Upgrading from v5.1.0 requires no protocol migration. In an independent
terminal, run `cc-remote update --check --version 5.1.1`, then
`cc-remote update --version 5.1.1`.

An older installed updater still uses its original logic until the new version
is activated. Legacy pending records without server launch receipts, and
receipts whose remote jobs have disappeared, still require reconciliation of
the original logs and public version. Do not delete records to force a retry.
See the [installation guide](https://github.com/muggle-stack/cc-remote/blob/v5.1.1/docs/installation_en.md).
Upgrades from protocol v82 or earlier still require coordinated device upgrades
under the deployment guide.

The release includes six Relay/Wrapper bundles, `install.sh` and `SHA256SUMS`,
with GitHub Actions regression tests, platform import checks and attestation.
It includes no new Desktop or mobile installer. Publishing does not deploy
services.
