# cc-remote v5.0.0

## 中文

v5.0.0 在 Claude Code 和 Codex 之外新增可选的 **DSH 0.2.1-rc.2** 接入，并集中修复历史合并、代理返回、阅读位置与文件预览体验。
通信协议从正式版 v4.0.29 的 **v79 升到 v82**；Claude Agent SDK 保持 **0.2.157**。

### DSH 接入

- 在现有 Code 界面选择 DSH、原生模式、模型、思考强度与权限；会话标题旁显示实际模式，外观按引擎独立保存。
- 支持原生命令、Skills、图片和文件、询问与审批、引导与排队、Goal、子代理和后台任务。逐级查看子代理过程、原生 PTC 工具层级及返回记录。
- 提供工作流、执行轨迹、预设、运行设置、插件包、自动化和终端面板；定时任务可直接通过表单创建。
- 终端使用统一选择器，改进输出流控、输入顺序、触摸历史滚动和居中布局；收起面板保留进程，断线不重发键盘输入。
- Artifacts 以当前会话的实际交付记录为依据，支持原生历史文件改动。浏览冷会话历史和产物不会启动模型轮次或占用驻留会话名额。
- 创建、派生、上传及控制使用持久化操作记录或禁止断线重放，避免响应丢失后重复写入。恢复排队任务时以原生真实终止状态为准，权限等设置与后续输入按顺序执行。

### Claude / Codex 与界面修复

- 按原生消息标识合并 Claude 实时文本、思考与历史，减少刷新后的重复内容；改进子代理返回、父代理继续处理、完成状态与通知。
- 切换引擎和会话时保留阅读位置、文件预览、居中布局及预览模式；修复链接图标、预览和 Markdown 换行展示。
- 展示已结束的 Claude 压缩摘要时保留正文结构；历史预取只缓存数据，到顶部再插入历史页，保留手动加载入口。
- 修复 Codex 失效子代理目录项和详情响应竞态；TUI 弹窗关闭后恢复图片，复用已有图片缓存。
- 降低回归测试开销，本地与 CI 的 pytest 默认使用两个 worker。保留 `-n 0` 串行诊断，CI 保存耗时报告；用户安装和更新不运行测试。

### 升级要求与边界

**v82 与 v79 不互通。** 安排所有设备的维护窗口，先等待进程内 Claude、临时侧聊和排队消息结束，按[部署流程](https://github.com/muggle-stack/cc-remote/blob/v5.0.0/deploy/README.md)协调切换 Relay/Web 和所有 Wrapper，再重新加载 Web/PWA。

已登记的 Release 安装可在独立终端运行：

```sh
cc-remote update --check --version 5.0.0
cc-remote update --version 5.0.0 --allow-protocol-change
```

设备更新先验证并更新 VPS，再更新当前设备；需要现有 SSH 管理权限，其余设备仍需逐一更新。上述参数不代表自动协调所有设备。失败回滚按各安装事务处理，不是跨机器的整体回滚。
独立 Claude 会话服务及原生 Codex daemon 沿用原有生命周期，普通 Wrapper 更新不会为升级强制重启它们。账号、配对和外部配置保留；历史缓存从 schema 48 升到 50 时重建聊天投影，原生会话记录不变。

- DSH 是可选组件；不使用 DSH 的 Claude/Codex 用户无需安装 Node 或 DSH。接入 DSH 时需另行准备指定原生版本、元数据插件及本机配对，见 [DSH 接入说明](https://github.com/muggle-stack/cc-remote/blob/v5.0.0/docs/dsh-integration.md)。发布包包含适配插件，不会自动安装、升级或迁移 DSH。
- 旧 DSH 会话及其子代理可能分别需要原生格式迁移。主会话可用不代表所有旧子代理已迁移；cc-remote 的只读历史入口不会代做迁移。
- DSH Work、会话删除和临时侧聊不提供；侧聊入口保持禁用。插件市场显示官方尚未提供能力，本机插件管理保留。Claude/Codex 侧聊不受影响。
- 发布提供六个 Relay/Wrapper 平台包、`install.sh` 和 `SHA256SUMS`，由 GitHub Actions 构建并生成 attestation。原生移动端源码未改动，已有 Android/鸿蒙外壳无需重装；安装包见 [v4.0.29](https://github.com/muggle-stack/cc-remote/releases/tag/v4.0.29)。本次没有新的 iOS 或 Desktop 安装包。

发布本身不会切换线上服务。升级验证覆盖自动化回归、安装包导入、协议及状态迁移保护；不等同于所有平台的真实服务升级或移动端真机验收，也不发送真实模型请求。

## English

v5.0.0 adds optional **DSH 0.2.1-rc.2** support alongside Claude Code and Codex,
with fixes for history merging, agent returns, reading positions and previews.
The wire protocol advances from **v79 in v4.0.29 to v82**. Claude Agent SDK
remains pinned to **0.2.157**.

### Changes

- Use DSH in the existing Code UI with native presets, models, effort,
  permissions, commands, Skills, attachments, questions, approvals, steering,
  queues, Goals, subagents and jobs. Preserve nested process detail and native
  PTC tool hierarchy, with the actual session mode beside the page title.
- Add workflow, trajectory, preset, runtime-settings, plugin-package, schedule
  and terminal panels. Create native schedules from a form. Improve terminal
  flow control, ordered input, touch scrolling and centered layout; detaching
  keeps the shell alive and reconnect never replays keyboard input.
- Preserve artifact provenance and historical file changes. Cold history and
  artifact reads neither start a model turn nor consume resident session slots.
- Journal uncertain DSH writes or exclude them from reconnect replay. Recover
  queues from native terminal state, share resident capacity across engines,
  and order permission/settings changes before subsequent prompt admission.
- Reconcile Claude streamed text and thinking with canonical message IDs;
  preserve agent-return, continuation, completion and notification behavior.
  Retain reading positions and preview layout across navigation, fix link icons
  and Markdown breaks, and format completed Claude compaction summaries.
- Keep history prefetch cache-only, inserting pages at the top boundary.
  Repair Codex stale child catalogs and detail-response races, and restore
  cached TUI images when a modal closes.
- Reduce regression overhead and default local/CI pytest to two workers.
  Serial diagnostics remain available with `-n 0`; CI retains timing reports.
  User installations and updates do not run pytest or build the Web client.

### Upgrade and compatibility

**Protocol v82 cannot communicate with v79.** Schedule a maintenance window for
all devices, drain in-process Claude/BTW work and queued messages, and follow the
[deployment procedure](https://github.com/muggle-stack/cc-remote/blob/v5.0.0/deploy/README.md)
to coordinate Relay/Web and every Wrapper, then reload Web/PWA clients.

Registered Release installations can run `cc-remote update --check --version
5.0.0`, followed by `cc-remote update --version 5.0.0 --allow-protocol-change`
from an independent terminal. Device updates verify/update the VPS first, using
existing SSH administration access, then update the current device. Other
devices still need individual updates. Rollback is per installation, not a
distributed rollback of every machine.

Ordinary Wrapper updates preserve the independent Claude service and native
Codex daemon lifetimes, account configuration and pairing. The schema 48 → 50
history cache transition rebuilds chat projections without rewriting native
transcripts.

DSH remains optional. Claude/Codex-only installations do not need Node or DSH.
Using DSH requires its pinned native runtime, the bundled metadata extension
and explicit local pairing; see the
[integration guide](https://github.com/muggle-stack/cc-remote/blob/v5.0.0/docs/dsh-integration.md).
Updates do not install, upgrade or migrate DSH. Old parent/child session logs
may independently require native format migration; read-only history does not
perform it. DSH Work, session deletion and temporary side chat remain unavailable,
and the official plugin market is explicitly marked unsupported. Local plugin
management and Claude/Codex side chats remain available.

GitHub Actions builds and attests six Relay/Wrapper bundles, `install.sh` and
`SHA256SUMS`. Native mobile sources are unchanged; existing Android/HarmonyOS
shells need no reinstall, and their packages remain available in
[v4.0.29](https://github.com/muggle-stack/cc-remote/releases/tag/v4.0.29).
No new iOS or Desktop installer is included. Publishing does not deploy services.
Validation covers automated regressions, package imports and protocol/state
migration guards, not every platform's live upgrade or native mobile devices.
No live model prompts are sent by these checks.
